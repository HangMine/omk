# Local Operational Application Contract

## Scope

The local operating build may change generated dist files only after a successful compile and an owned backup. The source commit owns exactly the attachment preview source, two attachment regression files and six lines of usage documentation, plus this mission's Spec Kitty configuration/artifacts. Original 103 dirty files and original staged diff remain byte-identical.

## Observable Boundary

A newly started canonical OMK process resolves the rebuilt coding-agent dist entry and renders actual image pixels without browser ImageData. The compiled stream releases cancelled pending reads and all terminal waiters. No provider generation request is needed to verify these contracts.

## Safety Invariants

- Validation and original images sent to the model do not change.
- No execution-owner release or remote termination is inferred from an abort signal.
- Existing user processes are not terminated or hot-patched.
- No remote push/PR/release or new dependency installation occurs.
- A scoped clone pass is not a claim that the unrelated dirty shared workspace's full check passed.

## Failure and Recovery

A failed build/compiled check leaves the new state unaccepted; the operator can restore only the task-owned backed-up dist trees after binding checks. Never reset/stash/clean user source or weaken tests to declare success.
