# Spec 111: 완료 재확인 게이트 (`OMK_FINISH_CONFIRM`) — 초안

상태: 초안(저장소 미커밋) · 기본값 off · 작성 2026-10-22 KST

## 1. 문제
모델이 첫 번째 "완료" 선언을 하면 바로 종료돼요. 검증이 덜 된 상태로 채점되는 실패가 생길 수 있어요. 이건 가설이고, 이 실패의 빈도는 아직 잰 적이 없어요.

## 2. 변경 (플래그 on일 때만)
1. 런에서 처음 완료를 선언하면 바로 종료하지 않아요. 대신 확인 메시지를 한 번 주입해요.
   - 확인 메시지 내용: 현재 워크스페이스와 터미널 상태 요약(최근 명령 출력 꼬리, `git status --short` 요약), 그리고 "채점되면 더 고칠 수 없어요. 확실하면 다시 완료를 선언하세요."
2. 그다음 완료 선언이 나오면 무조건 종료해요.
3. **런당 확인은 최대 1회로 강제해요.** 확인 뒤에 모델이 작업을 이어 가다가 다시 완료를 선언해도 다시 묻지 않아요.
   - Terminus 2는 다시 물을 수 있어요. 확인 응답에서 완료를 다시 표시하지 않으면 `_pending_completion`이 False로 돌아가기 때문이에요(L1624). 이 점이 Terminus 2와 달라요.
4. 확인 단계도 기존 턴, 시간, 토큰 예산 안에서 써요. 예산을 늘리지 않아요.

## 4. 테스트 (단위 테스트, 유료 실행 없이)
- off: 완료를 선언하면 바로 종료해요. 기존 동작과 바이트 단위로 같아야 해요.
- on: 첫 완료 → 확인 메시지 1회 → 두 번째 완료 → 종료.
- **무한 반복 방지**: 모델이 매 턴 완료를 선언하는 가짜 모델에서 확인 메시지가 정확히 1회만 나와야 하고, 종료까지 걸리는 턴은 2턴 이하여야 해요.
- 확인 뒤에 작업 → 다시 완료: 추가 확인 없이 종료해요.
- 완료를 선언하지 않은 채 예산이 끝나면 기존 종료 경로를 그대로 타요.

## 5. 사전등록 판정 (pilot 전에 고정, 변경 불가)
- 설계: 같은 모델, 같은 effort로 off/on을 짝지어 비교해요. 분석 단위는 작업 클러스터예요(cluster bootstrap 또는 GEE).
- **비열등성**: 해결률/accuracy 차이(on − off)의 작업 클러스터 95% CI 하한이 **−3점보다 커야** PASS예요.
- 가드레일: 턴당 토큰 ≤ 1.10x, 실행 시간 ≤ 1.25x
- pilot
  - 크기는 시작 전에 이 spec에 고정해요(Bench Analyst가 값을 채워요: `PILOT_N = 180`: 작업 30개 × 2 arm × 3회, 벤치마다 따로). 작업은 본 측정과 같은 세트에서 무작위로 30개를 뽑고, 실행은 본 측정과 따로 해요(K를 줄이지 않기 위해서예요). n은 Var(d)의 단측 80% 상한(df 29, ×1.2903, Browne)으로 정해요.
  - pilot은 ρ와 분산 추정에만 써요. pilot 데이터는 판정에서 빼요.
  - pilot으로 "CI 하한이 −3점을 넘을 수 있는 n"을 계산하고, 그 n을 spec에 커밋해요.
  - 무료 실행으로 그 n에 닿을 수 없으면 본 측정 전에 **"판정 불가(inconclusive)"**로 커밋하고 본 측정은 건너뛰어요. n은 나중에 늘리지 않아요.
- **기본값을 켜는 건 별도 spec으로만** 해요. 이 spec으로는 PASS가 나와도 옵트인 상태로 둬요.
