# Feature Specification: skill candidates from the `!omk` hub router

Status: PREREG frozen; free gate FAIL at G2 (pre-measure)
Branch: `spec/092-hub-router-skills` · Base: origin/main `86e5044a7b`

## Problem

Spec 091 stage 2 attached local bm25 candidates from the full skill catalog. Its free gate failed:
gold skill missed in 39/100 EN sentences (gate was ≤1/100). Cause: candidates were any doc with bm25
score > 0, capped at 64, so the gold skill was often below the cap or scored 0. Stage 2 is closed (091 gate FAIL).

The user (인호) asked to attach only related skills, via the existing `!omk` hub groups
(`omk-frontend`, `omk-backend-data`, `omk-loop`, `omk-plan`, ...; fallback `omk-skills`):
the hub router picks one hub, and only that hub's member skills become candidates.

## Design

1. Router: reuse `resolveOmkHubRoute` in `packages/coding-agent/src/core/bang-skill-invocation.ts`
   unchanged (deterministic: exact first-token alias match; else score aliases +4 / keywords +2 per
   token hit, highest score wins, ties by table order; score 0 → `omk-skills`). No model call.
2. Hubs (12 + fallback, from `OMK_HUB_ROUTES`): omk-frontend, omk-backend-data, omk-loop, omk-plan,
   omk-engineering, omk-security, omk-devops-release, omk-research-docs, omk-design-media,
   omk-agent-ops, omk-product-ops, omk-workspace-ops; fallback omk-skills.
3. Membership: hub → member skills is taken from each hub skill's SKILL.md body (the skills it lists).
   The membership table is frozen as a file with its sha256 before measuring (see PREREG).
   Skills listed by no hub keep their place in the sample; their gold hub is `omk-skills`.
4. Candidate block: members of the routed hub rendered with the 091 `renderCandidates` format
   (`<skill_candidates>` / name, description, location). Routed to `omk-skills` → no candidate block
   (only the index skill, as today).
5. Flag: `OMK_HUB_SKILL_CANDIDATES=1`, default off. Off = byte-identical to main.

### Scoring (R1, decided by Tech Lead)

- Hit iff routed hub == gold skill's membership hub, including gold = `omk-skills`.
  Hits for gold = `omk-skills` are also reported separately.
- No-answer (10): routed to `omk-skills` = correct; any other hub = false attach.
- Exact-skill accuracy (gold skill in candidates) reported, not gated.

### Gates (hub level)

- G1: hub-level miss ≤ 1/100.
- G2: if any hub, including `omk-skills`, has > 25 skills, the 092 free gate is FAIL without measuring.
  No list edits. The next step is then the paid all-217 arm, only with 인호's 1:1 OK.
- G3: per-hub candidate block ≤ 32k tokens.
- G4: no-answer false attach ≤ 1/10.

### Result of the pre-measure check: G2 FAIL

omk-engineering 34, omk-skills 35 and omk-agent-ops 28 are over 25. By G2 the 092 free gate is **FAIL** and the EN
set is not measured. G3 passes (max 4,193). The paid all-217 Jev arm needs its own spec criteria
(accuracy lower bound, no-answer false-attach upper bound, token/cost cap) and 인호's 1:1 OK first.

## Catalog description bug (catalog-v2)

`catalog_v2.py` read `description:` with a single-line regex, so YAML block scalars (`description: >-` and
multi-line descriptions) became the literal `>-`. 55 entries were affected (54 selectable, 1 disabled).
`tools/catalog_v3.py` keeps the same entries and re-parses those descriptions with the block-scalar parser in
`omk-eval-091/fm.py`; none are still broken. The 091 bm25 gate ran on catalog-v2, so 54 of the skills it searched
had no usable description. That is a confound in the 091 miss count (39/100), not a reason to reopen the result.

The 091 figure counted name + description only; the 092 draft rendered the full block including paths.
Agreed number for the cap: the full rendered block (what is actually sent) with catalog-v3, all 217 =
**26,088 tokens**, ≤ 32k. The draft's 89,577 chars was an earlier hand estimate; it is replaced by the numbers above.

## Known risks

- Hubs are coarse; membership is word-overlap based and puts 35 skills in the fallback.
- The router matches exact tokens only (no stemming). The first token of a skill name can hit an alias exactly.
- The same EN set is reused from 091 (router never tuned on it; lists frozen).

## Rollback

Flag default off; remove the flag path. No change to router or main behaviour.
